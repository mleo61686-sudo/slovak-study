# Flunio: сова для непрочитаних оновлень

## Встановлення

1. Лише в гілці `courses-ui`: розпакувати ZIP у корінь проєкту зі збереженням структури папок. Перед заміною файлів зробити резервні копії.
2. `npx prisma migrate deploy` — додає **nullable** поле `lastSeenUpdateKey` у таблицю `User`. Це реальна міграція БД, тому виконайте після резервного копіювання БД, спершу в тестовому середовищі. Не виконувати автоматично під час розпакування ZIP.
3. `npm run build` — вже включає `prisma generate`.
4. `npm run dev`, відкрити головну.

## Як перевірити не публікуючи новину

У режимі `npm run dev` відкрийте `http://localhost:3000/?owlPreview=1` — сова з'явиться примусово **тільки в development**. У звичайному режимі вона не показуватиме застарілі новини.

## Публікація новини

При додаванні запису з датою `2026-11-03` або пізніше до `app/updates/updates.ts` сова автоматично стане видимою тим, хто його ще не відкривав. За основу ключа береться дата та український заголовок (`date::title.ua`). Для двох публікацій того самого дня заголовки мають бути різними. Не змінюйте заголовок уже опублікованого запису без потреби: це може сприйматися як нова версія.

## Поведінка

- Гості: `localStorage` у цьому браузері.
- Авторизовані: колонка `User.lastSeenUpdateKey` у Postgres + локальний кеш. Перегляд синхронізується між пристроями.
- Відкриття `/updates` позначає останнє оновлення як переглянуте (незалежно від кнопки, через яку відкрили сторінку).
- Втрата мережі: індикатор не нав'язується; повторна синхронізація зможе виконатися під час наступного входу.
- Прев'ю `owlPreview=1` не позначає оновлення як прочитане й не працює у production.
- Дві теми та наявні стилі не змінені. Сова — власний SVG+CSS, без додаткових пакетів чи зображень.

## Відкат

Відновіть замінені файли з резервних копій, видаліть лише нові файли патча. У БД колонку можна залишити — вона nullable й не заважає старому коду. НЕ видаляйте колонку без потреби, щоб не втратити вже збережені стани.
